The `Curaduría de Activos` router manages the full editorial review lifecycle for AI-generated content assets. Assets are created by the async worker pipeline and enter the curation queue with `estado = "generado"`. Curators use these three endpoints to browse the queue, inspect the original source messages that informed each asset, edit the generated copy (each change is auto-versioned), and move assets through the review state machine until they are approved for distribution.

---

## GET /api/curaduria/activos

Returns a paginated, filterable list of content assets. Results are ordered by `fecha_actualizacion` descending so the most recently modified assets appear first. All counting and filtering is performed by PostgreSQL, supporting 3,000+ records without loading the full table into memory.

### Query parameters

<ParamField query="page" type="integer" default="1">
  Page number to retrieve. Must be ≥ 1.
</ParamField>

<ParamField query="limit" type="integer" default="15">
  Number of assets per page. Minimum 1, maximum 100.
</ParamField>

<ParamField query="estado" type="string">
  Filter by curation state. Accepted values from `EstadoActivoEnum`:

  | Value | Meaning |
  |---|---|
  | `generado` | Newly created by the AI pipeline, awaiting first review |
  | `revisado` | Curator has reviewed; may still need approval |
  | `aprobado` | Approved for distribution |
  | `rechazado` | Rejected; can be sent back to `revisado` for rework |
</ParamField>

<ParamField query="formato" type="string">
  Filter by content format. Accepted values from `FormatoActivoEnum`:

  | Value | Description |
  |---|---|
  | `linkedin` | Short-form post for LinkedIn |
  | `faq` | Frequently asked question with answer |
  | `newsletter` | Long-form newsletter section |
</ParamField>

### Response fields

<ResponseField name="items" type="array">
  Page of asset objects matching the query.

  <Expandable title="ActivoResponse fields">
    <ResponseField name="id_activo" type="string">
      Unique asset identifier.
    </ResponseField>
    <ResponseField name="formato" type="string">
      Content format: `linkedin`, `faq`, or `newsletter`.
    </ResponseField>
    <ResponseField name="titulo" type="string">
      Asset title generated by the pipeline.
    </ResponseField>
    <ResponseField name="copy" type="string">
      Current copy text (may have been edited by a curator).
    </ResponseField>
    <ResponseField name="estado" type="string">
      Current curation state.
    </ResponseField>
    <ResponseField name="fuentes" type="array of strings">
      List of `id_mensaje` values of the source messages that were used to generate this asset.
    </ResponseField>
    <ResponseField name="version" type="integer">
      Copy version counter. Starts at 1; incremented each time `copy` is sent via PATCH and its value differs from the currently stored text.
    </ResponseField>
    <ResponseField name="comentario_curador" type="string | null">
      Most recent curator comment. Overwritten (not appended) on each PATCH.
    </ResponseField>
    <ResponseField name="fecha_creacion" type="string (datetime)">
      ISO 8601 timestamp of when the asset was first created by the pipeline.
    </ResponseField>
    <ResponseField name="fecha_actualizacion" type="string (datetime)">
      ISO 8601 timestamp of the most recent change to any field.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of assets matching the current filters in the database.
</ResponseField>

<ResponseField name="page" type="integer">
  Current page number.
</ResponseField>

<ResponseField name="limit" type="integer">
  Page size used for this response.
</ResponseField>

<ResponseField name="total_pages" type="integer">
  Total number of pages — `ceil(total / limit)`.
</ResponseField>

### Example request

```bash
curl "http://127.0.0.1:8080/api/curaduria/activos?estado=generado&limit=5"
```

### Example response

```json
{
  "items": [
    {
      "id_activo": "act-77",
      "formato": "linkedin",
      "titulo": "Logro destacado — semana 38",
      "copy": "¡Logro destacado esta semana! Luisa finalizó el bootcamp con 98 puntos. #Comunidad",
      "estado": "generado",
      "fuentes": ["m-101"],
      "version": 1,
      "comentario_curador": null,
      "fecha_creacion": "2026-09-15T12:00:42Z",
      "fecha_actualizacion": "2026-09-15T12:00:42Z"
    }
  ],
  "total": 24,
  "page": 1,
  "limit": 5,
  "total_pages": 5
}
```

## GET /api/curaduria/activos/{id_activo}

Returns the full detail of a single asset, including the complete text of each source message that was used to generate it. The `fuentes_detalle` array is built by joining `activo.fuentes` (list of IDs) against the `mensajes` table.

### Path parameter

<ParamField path="id_activo" type="string" required>
  The unique asset identifier.
</ParamField>

### Response fields

All fields from `ActivoResponse` (see above), plus:

<ResponseField name="fuentes_detalle" type="array">
  Full source message objects retrieved from the `mensajes` table.

  <Expandable title="FuenteMensajeDetalle fields">
    <ResponseField name="id_mensaje" type="string">
      Message identifier.
    </ResponseField>
    <ResponseField name="autor" type="string">
      Author display name.
    </ResponseField>
    <ResponseField name="canal" type="string">
      Channel where the message was posted.
    </ResponseField>
    <ResponseField name="fecha" type="string">
      ISO 8601 timestamp of the original message.
    </ResponseField>
    <ResponseField name="texto" type="string">
      Full text of the source message (ground truth).
    </ResponseField>
  </Expandable>
</ResponseField>

### Example request

```bash
curl http://127.0.0.1:8080/api/curaduria/activos/act-77
```

### Example response

```json
{
  "id_activo": "act-77",
  "formato": "linkedin",
  "titulo": "Logro destacado — semana 38",
  "copy": "¡Logro destacado esta semana! Luisa finalizó el bootcamp con 98 puntos. #Comunidad",
  "estado": "generado",
  "fuentes": ["m-101"],
  "version": 1,
  "comentario_curador": null,
  "fecha_creacion": "2026-09-15T12:00:42Z",
  "fecha_actualizacion": "2026-09-15T12:00:42Z",
  "fuentes_detalle": [
    {
      "id_mensaje": "m-101",
      "autor": "luisa_data",
      "canal": "logros",
      "fecha": "2026-09-15T09:00:00Z",
      "texto": "Terminé el proyecto final del bootcamp con 98 puntos."
    }
  ]
}
```

### Error codes

| Status | Condition |
|---|---|
| `404` | No asset with the given `id_activo` exists |

## PATCH /api/curaduria/activos/{id_activo}

Updates one or more fields of an asset. All three fields are optional — send only the fields you want to change. Copy edits are auto-versioned; state changes are validated against the curation state machine before being committed.

### Path parameter

<ParamField path="id_activo" type="string" required>
  The unique asset identifier.
</ParamField>

### Request body

<ParamField body="copy" type="string">
  Replacement copy text. Minimum 5 characters. If provided and different from the current value, `version` is incremented by 1 automatically.
</ParamField>

<ParamField body="estado" type="string">
  Target curation state. Must be a valid transition from the asset's current state (see table below). Attempting an invalid transition returns `422`.
</ParamField>

<ParamField body="comentario_curador" type="string">
  Curator note. Maximum 500 characters. **Always overwrites** the previous comment — it is not appended.
</ParamField>

### State machine transitions

The following table shows every valid `from → to` state transition. Any other combination returns `422 Unprocessable Entity`.

| From | Allowed targets |
|---|---|
| `generado` | `revisado`, `rechazado` |
| `revisado` | `aprobado`, `rechazado`, `generado` |
| `aprobado` | `revisado` |
| `rechazado` | `revisado` |

<Warning>
  Invalid transitions return HTTP **422** with the detail message: `"Transición inválida: no se puede pasar de '{estado_actual}' a '{estado_solicitado}'."` The asset is **not** modified.
</Warning>

### Example request

```bash
curl -X PATCH http://127.0.0.1:8080/api/curaduria/activos/act-77 \
  -H "Content-Type: application/json" \
  -d '{
    "copy": "¡Gran logro esta semana! Luisa completó el bootcamp con 98 puntos. ¡Felicitaciones! #CommunityHighlights",
    "estado": "revisado",
    "comentario_curador": "Copy ampliado con saludo y hashtag oficial."
  }'
```

### Response `200 OK`

Returns the updated `ActivoResponse` object (same schema as the list endpoint — note that `fuentes_detalle` is **not** included; use the detail endpoint for that):

```json
{
  "id_activo": "act-77",
  "formato": "linkedin",
  "titulo": "Logro destacado — semana 38",
  "copy": "¡Gran logro esta semana! Luisa completó el bootcamp con 98 puntos. ¡Felicitaciones! #CommunityHighlights",
  "estado": "revisado",
  "fuentes": ["m-101"],
  "version": 2,
  "comentario_curador": "Copy ampliado con saludo y hashtag oficial.",
  "fecha_creacion": "2026-09-15T12:00:42Z",
  "fecha_actualizacion": "2026-09-16T08:14:05Z"
}
```

### Error codes

| Status | Condition |
|---|---|
| `404` | No asset with the given `id_activo` exists |
| `422` | Invalid state transition or `copy` is shorter than 5 characters |
