---
title: "Get started with CommunityLab in 5 minutes"
sidebarTitle: "Quickstart"
description: "Clone the repo, configure environment variables, and start the full Docker Compose stack to ingest your first batch of community messages."
---

This guide walks you through spinning up the complete six-service CommunityLab stack on your local machine, ingesting a sample batch of Discord messages via the API, and viewing the generated content assets in the curation dashboard — all without any external API keys. By the end you will have a running instance of the proxy (port 8080), Next.js frontend (3000), FastAPI backend (8000), async worker, schema-init job, and PostgreSQL database, with at least one generated asset visible in the curation panel.

---

<Info>
  **Prerequisites before you begin:**
  - **Docker** and **Docker Compose** v2 (`docker compose` — note: no hyphen). Verify with `docker compose version`.
  - **Git** to clone the repository.
  - **Python 3.12** (optional — only needed if you want to run the LangGraph pipeline or backend locally outside Docker).
  - An x86-64 or Apple Silicon (ARM64) machine. The Compose file targets `linux/arm64` by default; Intel/AMD users set `DOCKER_PLATFORM=linux/amd64` in `.env`.
</Info>

<Steps>
  <Step title="Clone the repository">
    Clone the monorepo and enter the project root. All subsequent commands assume you are running from this directory.

    ```bash
    git clone https://github.com/No-Country-simulation/G10-CommunityLabE32.git
    cd G10-CommunityLabE32
    ```
  </Step>

  <Step title="Create your .env file">
    Copy the example environment file to `.env` and fill in the required values. The `.env` file is git-ignored — never commit it.

    ```bash
    cp .env.example .env
    ```

    Open `.env` in your editor and set at minimum `POSTGRES_PASSWORD`. The worker will refuse to start if `POSTGRES_PASSWORD` is empty. The full set of variables and their defaults:

    ```ini
    # Database
    POSTGRES_DB=communitylab
    POSTGRES_USER=communitylab
    # Required: choose a strong password, e.g. POSTGRES_PASSWORD=changeme123
    POSTGRES_PASSWORD=changeme123

    # Docker platform
    # ARM64 (Apple Silicon, OCI Ampere): linux/arm64 (default)
    # Intel/AMD: linux/amd64
    DOCKER_PLATFORM=linux/arm64

    # Proxy binding
    HTTP_BIND_ADDRESS=127.0.0.1
    HTTP_PORT=8080

    # Worker mode
    # simulado — full pipeline with mocked AI, no external keys required
    # openrouter — calls real LLMs via OpenRouter (requires OPENROUTER_API_KEY)
    WORKER_MODE=simulado

    # Leave blank when using simulado mode
    OPENROUTER_API_KEY=
    ```

    <Tip>
      Use `WORKER_MODE=simulado` for local development and demos. The pipeline runs end-to-end — ingestion, scoring, routing, generation, and consolidation — using simulated AI responses so you do not need a Gemini or OpenRouter API key. Switch to `WORKER_MODE=openrouter` (and set `OPENROUTER_API_KEY`) only when you want real model inference.
    </Tip>
  </Step>

  <Step title="Build and start the stack">
    Build all images and start the six services in detached mode. The first build takes 3–5 minutes as it downloads base images and installs Python/Node dependencies.

    ```bash
    docker compose up --build -d
    ```

    Docker Compose starts the services in dependency order:

    | Service | Port | Role |
    |---|---|---|
    | `postgres` | internal | PostgreSQL 16 database with persistent volume |
    | `db-init` | — | One-shot schema migration; runs `worker.init_db` and exits |
    | `api` | 8000 (internal) | FastAPI backend; waits for `postgres` and `db-init` |
    | `worker` | — | Async job processor; polls `trabajos_worker` queue |
    | `web` | 3000 (internal) | Next.js frontend; proxies API calls to `http://api:8000` |
    | `proxy` | **8080** (host) | Nginx reverse proxy; routes `/api/*` → api, `/` → web |

    Watch the startup logs until all services are healthy:

    ```bash
    docker compose ps
    ```

    All services should show `healthy` or `running` status before you proceed.
  </Step>

  <Step title="Verify the API is healthy">
    Confirm the full proxy → API path is working by hitting the health endpoint:

    ```bash
    curl -s http://127.0.0.1:8080/health
    ```

    Expected response:

    ```json
    {
      "estado": "ok",
      "servicio": "communitylab-api"
    }
    ```

    If you get a connection refused error, check that the proxy service is healthy: `docker compose logs proxy`.
  </Step>

  <Step title="Open the dashboard">
    Navigate to the frontend in your browser:

    ```
    http://127.0.0.1:8080
    ```

    The dashboard loads the CommunityLab interface. At this point the database is empty — no messages, no assets. The next step sends the first batch.
  </Step>

  <Step title="Review assets in the curation panel">
    Open the curation panel to inspect the generated assets and approve them for publication:

    ```
    http://127.0.0.1:8080/curaduria
    ```

    The panel shows all assets with `estado = generado`. For each asset you can:
    - Read the generated copy and inspect the source message references in `fuentes[]`.
    - Add a curator comment.
    - Advance the status to `revisado` or `aprobado`.
    - Reject an asset with `rechazado` to exclude it from publication.

    Assets promoted to `aprobado` are ready for export. OCI Object Storage persistence is planned and will be triggered from this step in a future release.
  </Step>

<Accordion title="Run the backend locally without Docker">
  If you want to iterate on the FastAPI backend without rebuilding Docker images, you can run it directly with a local virtual environment. You still need a running PostgreSQL instance (you can keep using the Docker Compose `postgres` service).

  **1. Create and activate a virtual environment:**

  ```bash
  python3 -m venv .venv
  source .venv/bin/activate   # macOS / Linux
  # .venv\Scripts\activate    # Windows
  ```

  **2. Install backend dependencies:**

  ```bash
  pip install -r backend/requirements.txt
  ```

  **3. Export the required environment variables:**

  ```bash
  export DATABASE_URL="postgresql+asyncpg://communitylab:changeme123@127.0.0.1:5432/communitylab"
  export OPENROUTER_API_KEY=""
  ```

  Replace `changeme123` with the value of `POSTGRES_PASSWORD` in your `.env` file. Make sure the `postgres` container is running (`docker compose up -d postgres db-init`) before starting the API.

  **4. Start the API with hot-reload:**

  ```bash
  python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
  ```

  The API is now available at `http://127.0.0.1:8000`. Interactive Swagger docs are at `http://127.0.0.1:8000/docs`. The Next.js frontend will proxy `/api/*` requests to this local process if you also run it with `npm run dev` in the `frontend/` directory.
</Accordion>

<Tip>
  **`simulado` vs `openrouter` worker modes:**
  - `WORKER_MODE=simulado` — the async worker runs the complete LangGraph pipeline using hard-coded stub responses. No external API calls are made. Generated assets are marked `[SIMULADO] — NO PUBLICAR`. This is the right mode for local development, CI, and demos.
  - `WORKER_MODE=openrouter` — the worker sends scoring and generation prompts to real language models via the OpenRouter API. You must set `OPENROUTER_API_KEY` to a valid key. Assets generated in this mode are suitable for real curation and publication. This mode incurs API costs per batch processed.
</Tip>
